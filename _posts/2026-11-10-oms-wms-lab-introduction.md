주문(OMS)과 창고(WMS)가 만나는 지점의 문제를 풀어 보기 위해 **oms-wms-lab**을 시작했다. 주문부터 결제, 재고 차감, 출고, 취소까지 이어지는 흐름을 다루는 개인 학습 프로젝트다.

프로젝트 코드는 [GitHub 저장소](https://github.com/sshyuny/oms-wms-lab)에서 볼 수 있다.

## 어떤 프로젝트인가

이미 동작하는 프로젝트에 합류해 기존 코드를 파악하고, 기능을 유지하면서 문제를 해결하는 상황을 재현하고 싶었다. 이를 위해 주문·결제·출고·취소가 동작하는 기본 코드를 AI(Claude)로 만들고, 버그와 새로운 업무 요구를 단계별 과제로 준비했다.

기본 코드는 AI가 작성한 출발점이다. 이후에는 증상 재현, 원인 진단, 해법 결정을 직접 한다. 코드를 직접 작성하거나 구체적인 지시를 통해 AI의 도움을 받고, AI가 작성한 변경에는 커밋에 공동 작성자 표시를 남긴다.

## 다루는 업무 흐름

출발점은 창고 한 곳을 기준으로 다음 흐름을 제공한다.

- 상품 등록과 재고 수량 관리
- 여러 상품을 담은 주문 생성과 배송비·쿠폰 할인 계산
- 가짜 PG를 통한 결제 승인과 취소
- 결제 후 출고지시 생성과 피킹·패킹·출고 완료 처리
- 출고 전 주문의 전체 취소와 환불

UI 없이 API와 테스트로 동작을 확인한다. 회원·인증, 실제 PG 연동, 창고 내 로케이션과 피킹 경로 등은 초기 범위에서 제외했다.

## 어떻게 진행하나

단계마다 증상이나 요구사항이 적힌 이슈를 받아 아래 순서로 진행한다.

1. 기존 동작을 확인하고 문제를 실패하는 테스트로 재현한다.
2. 원인을 진단하고 해결 방향을 정해 코드를 수정한다.
3. 기존 테스트와 재현 테스트로 변경을 검증한다.
4. PR에 원인, 선택한 해법, 선택하지 않은 대안과 남은 위험을 기록한다.

지금까지는 동시 주문 시 재고가 음수로 떨어지는 문제와, 미결제 주문에 묶인 재고 때문에 신규 주문이 막히는 문제를 다뤘다. 앞으로는 출고 장애가 결제에 미치는 영향, 다중 창고와 분할 출고, 부분 취소, 반품과 부분 환불로 범위를 넓힐 계획이다.

## 기술 구성

Java 25와 Spring Boot 4.1.1을 사용하며, JPA·MySQL·Flyway로 데이터와 스키마를 관리한다. 빌드는 Gradle 단일 모듈로 구성했다.

테스트와 로컬 실행에서도 Testcontainers로 MySQL을 띄운다. 동시성과 락 관련 문제를 실제 사용할 DB의 동작에 가깝게 재현하기 위해서다.

이 카테고리에는 각 단계에서 어떤 증상을 관찰했고, 왜 해당 해법을 선택했으며, 어떻게 검증했는지 기록하려고 한다.
